很多人第一次搭 RAG，都会盯着向量库返回的 score 做阈值过滤：score > 0.8 才算相关。跑通了 demo，上线后却发现同一套阈值换一批 query 就崩。问题不在向量库，在于我们误读了相似度分数的含义。

**余弦相似度是方向，不是距离**

对 L2 归一化后的向量，余弦相似度等于点积，取值 [-1, 1]。它衡量两个向量在超球面上的夹角：1 表示同向，0 表示正交，-1 表示反向。注意，它不关心模长。两个语义相近但一个信息密集、一个泛泛而谈的文本，可能夹角很小；而两段都啰嗦但主题不同的文本，夹角也可能不大。

更关键的是，**高维空间里随机向量的余弦相似度分布并不是以 0 为中心**。以 1536 维为例，均匀随机向量的余弦相似度标准差约 1/√d ≈ 0.026，绝大多数随机对落在 ±0.08 内。这意味着 0.1 和 0.2 的差距，在统计上可能比你想的显著得多；而 0.75 和 0.78 的差距，可能只是噪声。阈值不是拍脑袋定的，得看你的 embedding 模型在真实数据上的分数分布。

**分数不可跨模型比较**

这是最常被忽略的坑。不同 embedding 模型的训练目标、温度、归一化方式都不同。OpenAI text-embedding-3-small 的“相关”可能集中在 0.3–0.5，而 BGE-M3 可能集中在 0.6–0.8。把 A 模型调好的 0.75 阈值直接搬到 B 模型，等于刻舟求剑。换模型必须重新校准阈值，最好用带标注的 query-doc 对画 ROC 曲线，选 F1 最优点。

即使同一个模型，**不同领域的分数尺度也不同**。医学问答里，“高血压”和“血压升高”的相似度可能高达 0.9，因为术语高度共现；而在开放域闲聊里，0.6 就算很相关了。用全局阈值一刀切，必然在某个领域过召回、另一个领域欠召回。

**相似不等于相关**

向量检索召回的是“语义相近”，不是“能回答问题”。用户问“布洛芬的禁忌症”，检索到一段讲“布洛芬药理机制”的文本，相似度可能很高，但它不包含禁忌症答案。这就是典型的**主题相似但信息不匹配**。解决办法不是调高阈值，而是引入 reranker：用 cross-encoder 对 query 和候选 doc 做交互编码，直接输出相关性分数。Reranker 慢，但只对 top-50 做，成本可控。

另一个陷阱是**否定和反义**。Embedding 模型对“有效”和“无效”的区分往往很弱，因为训练数据里它们常出现在相似上下文。如果你的场景涉及否定、条件、剂量方向，纯向量检索会翻车。这时需要混合检索：BM25 抓关键词，向量抓语义，再用 RRF 融合。

**工程上的几个具体建议**

1. **记录分数分布**：每次检索把 top-k 的 score 打日志，按 query 类型分桶。上线一周你就能看到哪些 query 的分数整体偏低，是模型不匹配还是数据缺失。
2. **用相对排序而非绝对阈值**：如果只取 top-3，就别纠结 0.8 还是 0.75。真正需要阈值的是“无答案”判断——这时可以设一个保守阈值，宁可多召回让 LLM 判断，也不要漏。
3. **归一化要一致**：入库和查询必须用同一套归一化。有些库默认做 L2，有些不做，混用会导致分数尺度漂移。
4. **维度不是越高越好**：1536 维比 768 维表达力强，但存储和检索成本翻倍。Matryoshka embedding 允许你截断维度，前 256 维往往保留大部分语义，适合对延迟敏感的边缘场景。

**一个开放问题**

我还没想清楚：当 embedding 模型本身在领域数据上微调后，它的分数分布会整体偏移，这时旧阈值完全失效。有没有一种在线校准方法，不需要重新标注，就能根据检索结果的后续反馈（比如用户点击、LLM 引用）自动调整阈值？目前我试过用分位数动态截断，但冷启动阶段不稳定。欢迎有经验的朋友交流。

总之，把相似度分数当成“相关性概率”是危险的。它只是一个几何量，受模型、领域、维度、归一化共同影响。理解它的边界，比调参更重要。
