做 RAG 的人大概都踩过这个坑：拿两个不同 embedding 模型算出的余弦相似度直接比较，或者把 0.8 当成"相关"的通用阈值。分数本身没有错，错的是我们默认它携带了它并不携带的信息。

## 余弦相似度只是夹角，不是概率

对归一化向量，余弦相似度等于点积，取值范围 [-1, 1]。它衡量的是两个向量方向的一致性，仅此而已。它**不是**"这两段文本相关的概率"，也**不是**"这个 chunk 能回答问题的置信度"。把 0.85 读成"85% 相关"是范畴错误。

更麻烦的是，同一个模型在不同语料上分数分布完全不同。在短 query 对长 passage 的检索里，正样本分数可能集中在 0.6–0.75；换一个领域，正样本可能整体上移到 0.8 以上。固定阈值 0.7 在一个数据集上召回不错，换个数据集就全军覆没。

## 三个系统性陷阱

**1. 各向异性（anisotropy）。** 很多句向量模型输出的向量挤在一个狭窄的锥形区域里，任意两段无关文本的余弦相似度也有 0.6–0.8。这时候分数之间的**绝对差**才有意义，绝对值没有。BGE、E5 这类模型在训练时用了对比学习，情况好一些，但并没有消失。诊断方法很简单：随机抽 1000 对不相关句子算相似度，看均值和中位数。如果均值 0.7、标准差 0.05，那你的有效动态范围只有零点几，阈值必须按分位数定，而不是拍脑袋。

**2. 跨模型不可比。** 模型 A 的 0.8 和模型 B 的 0.8 没有任何关系。维度、训练目标、归一化方式都不同。切换 embedding 模型时，所有硬编码阈值、缓存、已入库向量全部要重建——这不是运维细节，是正确性问题。混用新旧向量做检索，结果会静默地错。

**3. query 与 document 的不对称。** 很多模型（如 E5、BGE）要求 query 加 `query:` 前缀、document 加 `passage:` 前缀，非对称训练。漏加前缀不会报错，只会让分数整体偏移、排序变差。这类 bug 最难查，因为系统"能跑"。

## 分数该怎么用

**用排序，不用绝对值。** top-k 检索的本质是排序，只要同一 query 下相对顺序对，分数绝对值漂移无所谓。需要截断时，用**相对**策略：取 top-1 分数的某个比例（如 0.9×top1），或取分数分布的拐点（相邻分数差最大的位置）。

**用分位数校准阈值。** 在代表性语料上跑一批真实 query，收集正负样本分数，画 ROC 或 PR 曲线，选满足召回目标的阈值。这个阈值只对当前模型 + 当前语料分布有效，换模型或换领域必须重做。

**用 reranker 做二次判断。** 向量召回负责高召回，cross-encoder reranker 负责精度。reranker 输出的是它自己的相关性分数，同样不是概率，但判别力通常强得多。工程上常见的组合是：向量召回 top-50，reranker 取 top-5，再用一个**校准过的**分类器或 LLM 判断是否真的能回答。

## 评估要评检索，不要评分数

我见过太多人盯着"平均相似度"调参。这个指标和最终答案质量的相关性很弱。真正该测的是：

- **Recall@k**：正确答案所在的 chunk 是否进了 top-k。这是 RAG 的天花板。
- **MRR / nDCG**：排序质量。
- **端到端答案准确率**：在固定生成模型下，换检索配置看答案对错的变化。

构造评估集时，负样本要包含"语义相近但答案不同"的难负例，否则指标虚高。比如问"术后镇痛首选"，负例里要有"术后抗感染首选"，而不是随便抓一段无关文本。

## 一个开放问题

多向量检索（ColBERT 式 late interaction）和稀疏-稠密混合检索（BM25 + embedding）在分数融合时，如何做无监督的分数校准？目前常用 RRF（reciprocal rank fusion），它只依赖排名、绕开了分数不可比的问题，但在两个检索器召回质量差异很大时会吃亏。我还没找到特别干净的解法，欢迎讨论。

一句话总结：embedding 分数是**几何量**，不是**语义概率**。把它当排序信号用，配合分位数校准和 reranker，系统就稳；把它当置信度用，迟早出事。
