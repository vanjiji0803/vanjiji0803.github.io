在构建 RAG 或语义搜索时，我们常把 embedding 的余弦相似度当作相关性的代理。但相似度分数只是一个几何量，它不直接等于语义相关性，更不等于答案正确性。理解它的局限，才能避免检索环节的隐性失败。

**相似度分数在度量什么**

给定两个向量 **a** 和 **b**，余弦相似度是点积除以模长乘积：cos(θ) = (a·b) / (||a|| ||b||)。它只关心方向，忽略长度。对于归一化后的向量，内积就等于余弦相似度。所以分数范围在 [-1, 1]，1 表示方向完全一致。

但 embedding 模型训练的目标通常是让语义相似的文本在向量空间中靠近，这个“相似”是训练数据定义的。如果训练数据里“苹果”和“橘子”经常出现在相似上下文，它们的向量就会靠近，即使它们不是同一种水果。因此，分数高只说明“在模型看来，这两段文本的上下文分布相似”，而不是“它们回答了同一个问题”。

**高相似度不等于相关**

一个经典陷阱是：查询“如何用 Python 读取 CSV 文件”，检索到一段“如何用 Python 写入 CSV 文件”的文本，相似度可能高达 0.95。因为两者共享大量词汇和句式，但意图相反。另一个例子：查询“2024 年诺贝尔物理学奖得主”，检索到“2023 年诺贝尔物理学奖得主”，相似度也很高，但答案错误。

更隐蔽的是否定和条件。查询“不含乳糖的牛奶”，可能检索到“含乳糖的牛奶”，因为“不含”这个否定词在 embedding 中往往被弱化。模型可能把“不含乳糖”和“含乳糖”映射到相近区域，因为它们在训练数据中常一起出现。

**分数不可跨模型比较**

不同 embedding 模型（如 text-embedding-ada-002、bge-large、e5）的相似度分布完全不同。ada-002 的分数普遍偏高，0.8 可能只是“有点相关”；而 bge 的分数分布更分散，0.6 可能已经很强。因此，绝对阈值（如“只保留 >0.8”）是危险的。正确做法是在你的数据上采样，观察正负样本的分数分布，再选阈值。

**分数也不反映信息量**

一段文本可能和查询高度相似，但只重复了查询本身，没有新增信息。例如查询“Transformer 的自注意力机制”，检索到“Transformer 模型包含自注意力机制”，相似度极高，但对生成答案毫无帮助。这就是为什么需要 reranker：交叉编码器会同时看查询和文档，判断后者是否真的能回答前者，而不是仅仅“像”。

**如何正确使用分数**

1. **相对排序，而非绝对阈值**：用分数对候选排序，取 top-k，而不是卡一个全局阈值。如果必须卡阈值，按模型和数据分别校准。
2. **结合关键词过滤**：对否定、数字、专有名词等，用 BM25 或规则做混合检索。例如“不含乳糖”可以强制要求文档包含“不含”或“无乳糖”。
3. **用 reranker 做精排**：先召回 50-100 个候选，再用交叉编码器打分，取 top-5。这能显著减少“高相似度但无关”的噪声。
4. **监控分数分布**：在生产中记录每次查询的 top-1 分数、分数间隔（top-1 与 top-2 的差）。如果间隔很小，说明检索结果模糊，可能需要回退或澄清。
5. **不要用分数做置信度**：相似度不是概率。不要把它直接当作“答案正确的概率”展示给用户。

**一个实际例子**

假设我们有一个手术器械知识库，查询“电刀在凝血模式下的功率设置”。嵌入后，top-3 可能是：
- 文档 A：“电刀凝血模式通常使用 30-50W” —— 相似度 0.82
- 文档 B：“电刀切割模式使用 50-80W” —— 相似度 0.79
- 文档 C：“双极电凝的功率设置” —— 相似度 0.75

如果只看分数，A 最高，但 B 和 C 也很接近。此时如果阈值设为 0.8，会漏掉 B 和 C，而它们可能包含关键信息。更好的做法是取 top-3 全部交给 reranker，或者用混合检索确保“凝血”这个关键词被匹配。

**开放问题**

我还没找到一个通用的方法来自动校准不同模型的相似度阈值。目前只能靠标注数据做经验校准。另外，对于长文档，截断策略（取前 512 token 还是平均池化）会显著影响分数，但哪种更好仍取决于任务。如果你有更好的实践，欢迎讨论。

总之，embedding 相似度是一个有用的信号，但它只是信号，不是答案。理解它的几何本质和训练偏差，才能设计出鲁棒的检索系统。
