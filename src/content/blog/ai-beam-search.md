在部署 LLM 时，解码策略往往被当作一个超参数随手设置，但它直接决定了生成质量、多样性和延迟。这篇文章从机制出发，聊聊 beam search、采样、温度以及 top-k/top-p 的取舍。

## 自回归解码的基本问题

给定上下文 $x$，模型在每个时间步输出词表上的概率分布 $P(y_t | y_{<t}, x)$。解码就是从这个分布中选出一个 token，并递归下去。核心矛盾在于：我们想要全局最优序列，但精确搜索是指数级的。

## Beam search：用宽度换质量

Beam search 维护 $k$ 个候选序列（beam width），每步扩展所有候选并保留概率最高的 $k$ 个。它本质是启发式搜索，用 $k$ 控制计算量。

**优点**：在机器翻译等任务中，beam search 能显著提升 BLEU，因为它倾向于高概率、安全的输出。

**缺点**：
- **多样性坍塌**：beam search 生成的文本往往重复、空洞。原因在于它最大化序列概率，而高概率序列常是通用、乏味的。
- **长度偏差**：对数概率是负的，长序列概率更低，导致 beam search 偏好短输出。常用长度归一化（length penalty）缓解，但调参敏感。
- **计算成本**：每步需要 $k$ 次前向，显存和延迟随 $k$ 线性增长。

**实践建议**：对话和创意生成慎用 beam search；翻译、摘要等任务可尝试 $k=4$ 到 $8$，并配合长度惩罚。

## 采样：用随机性换多样性

采样按概率分布随机选 token。纯采样（ ancestral sampling）能产生多样输出，但容易跑偏，生成低概率、不连贯的内容。

### 温度（Temperature）

温度 $T$ 调整 logits：$P_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$。

- $T < 1$：分布更尖锐，高概率 token 更突出，输出更确定、保守。
- $T > 1$：分布更平坦，低概率 token 有机会被选中，输出更多样，但也更易出错。
- $T \to 0$：退化为贪心解码。

温度不改变排序，只改变相对差距。实践中 $T=0.7$ 到 $1.0$ 是常见起点。

### Top-k 采样

每步只从概率最高的 $k$ 个 token 中采样，避免长尾噪声。$k$ 固定，但不同上下文下分布形状不同：有时前 10 个 token 已覆盖 95% 概率，有时前 100 个才够。

### Top-p（核采样）

动态选择最小的 token 集合，使其累积概率超过 $p$（如 0.9），然后从中采样。它能自适应分布形状，通常比 top-k 更鲁棒。

**组合使用**：常见做法是温度 + top-p（如 $T=0.8, p=0.95$），或温度 + top-k。注意顺序：先温度缩放，再截断。

## 其他解码策略

- **对比搜索（Contrastive Search）**：在采样时惩罚与上下文相似的 token，平衡连贯性和多样性。
- **典型采样（Typical Sampling）**：选择接近分布熵的 token，避免过于平庸或离谱。
- **投机解码（Speculative Decoding）**：用小模型草稿，大模型验证，加速采样，不改变分布。

## 评估与调参

解码策略的评估不能只看困惑度。需要任务相关指标：
- 翻译：BLEU、COMET
- 摘要：ROUGE
- 对话：多样性（distinct-n）、连贯性（人工或模型评估）
- 代码：pass@k

**调参建议**：
1. 先确定任务需要确定性还是多样性。
2. 从贪心或低温度开始，逐步增加随机性，观察质量拐点。
3. 监控重复率（n-gram 重复比例）和自 BLEU，作为多样性代理。
4. 注意延迟：beam search 和 top-k 的 $k$ 都会增加计算，线上服务需权衡 QPS。

## 边缘部署的考量

在边缘设备（如 NVIDIA IGX/AGX）上跑 LLM 时，解码策略直接影响延迟和功耗。beam search 的 $k$ 倍计算可能让实时性崩溃；采样则每步只前向一次，更适合。若用 TensorRT 加速，注意 top-p 的排序操作可能成为瓶颈，可考虑固定 top-k 或使用融合核。
