构建 LLM Agent 时，最让人头疼的不是模型本身，而是当它表现异常时，你根本不知道发生了什么。传统的日志和指标在 Agent 场景下几乎失效：一次用户请求可能触发多轮 LLM 调用、工具执行和状态转移，错误往往隐藏在中间步骤。因此，我们需要一套专门针对 Agent 的可观测性体系，核心是 trace、span、prompt 记录、工具输出和失败分类。

## Trace 与 Span：结构化调用链

Trace 代表一次完整的用户请求生命周期，Span 则是其中的一个操作单元。对于 Agent，一个典型的 trace 可能包含：

- `agent.run` (根 span)
- `llm.chat` (每次模型调用)
- `tool.execute` (每次工具调用)
- `retrieval.search` (如果涉及 RAG)
- `planning.step` (规划步骤)

每个 span 需要记录：开始/结束时间、输入/输出、状态（成功/失败）、元数据（模型名、token 数、工具名）。关键是要保持父子关系，形成调用树。这样当最终回答错误时，你可以沿着树回溯，定位是哪个 span 引入了问题。

实现上，OpenTelemetry 是事实标准，但需要扩展以支持 LLM 特有的属性。例如，在 `llm.chat` span 中记录 `prompt_tokens`、`completion_tokens`、`model`、`temperature`，以及完整的 prompt 和 response（注意脱敏和采样）。对于工具调用，记录 `tool_name`、`arguments`、`result` 和 `error`。

## Prompt 记录：平衡细节与成本

记录完整 prompt 是调试的黄金标准，但会带来存储成本和隐私风险。我的做法是：

1. **采样**：生产环境按 1% 采样记录完整 prompt，错误请求 100% 记录。
2. **脱敏**：在记录前用正则或 NER 移除 PII（如邮箱、电话、身份证号）。
3. **哈希**：对 prompt 计算哈希，用于去重和快速检索相似请求。
4. **结构化**：将 prompt 拆分为 system、user、assistant 消息，分别存储，便于分析。

一个常见的坑是：多轮对话中，prompt 会累积历史消息，导致 token 数爆炸。记录时应该同时保存原始消息列表和最终拼接的字符串，以便分析上下文窗口的使用效率。

## 工具输出：不只是结果

工具调用的输出往往被简化为“成功/失败”，但实际需要记录更多：

- **原始输出**：工具返回的完整内容（可能很大，需截断或存储到对象存储）。
- **解析后输出**：如果工具返回 JSON，记录解析后的结构，以及解析错误。
- **延迟**：工具执行耗时，区分网络延迟和计算延迟。
- **副作用**：如果工具修改了外部状态（如写数据库），记录变更摘要。

例如，一个搜索工具返回了 10 条结果，但 Agent 只用了第 3 条。记录时应该保存全部结果和 Agent 的选择，这样才能分析检索质量。

## 失败分类：从现象到根因

Agent 的失败模式比传统软件更复杂。我根据实际经验，将失败分为几类：

1. **规划失败**：Agent 制定了错误的步骤序列，或陷入循环。
2. **工具选择失败**：选错了工具，或参数格式错误。
3. **工具执行失败**：工具本身报错或超时。
4. **上下文失败**：关键信息被截断或丢失，导致模型幻觉。
5. **输出解析失败**：模型返回的格式不符合预期（如 JSON 解析错误）。
6. **安全/策略失败**：触发了内容过滤或权限限制。

每类失败需要不同的监控指标。例如，规划失败可以通过“步骤数超过阈值”或“重复调用同一工具”来检测；上下文失败可以通过“prompt 长度接近窗口上限”来预警。

## 实现细节与权衡

- **异步记录**：span 的写入不能阻塞主流程，使用队列批量写入。
- **成本控制**：记录完整 prompt 和工具输出会显著增加存储成本，需要设置 TTL 和采样策略。
- **关联 ID**：为每个 trace 生成唯一 ID，并透传到所有下游服务，便于跨系统追踪。
- **可视化**：用树形图展示 trace，支持按时间、状态过滤，并高亮错误 span。

一个开放问题是：如何自动诊断失败根因？目前我主要靠人工分析 trace，但正在尝试用规则引擎对失败分类打标，再结合 LLM 做根因摘要。这本身又是一个 Agent 任务，有点递归的意味。

总之，可观测性不是事后补救，而是 Agent 设计的一部分。在写第一行代码时，就应该考虑如何记录、如何追踪、如何分类失败。否则，你面对的将是一个黑盒，而调试黑盒的代价，远高于提前埋点。
