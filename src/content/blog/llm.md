幻觉不是模型“坏了”，而是概率生成机制在开放空间里的必然产物。在生产系统中，我们无法消灭幻觉，只能通过多层约束把它压到可接受范围。下面是我在手术 Agent 和边缘部署中总结的几层防线，每层都有代价和失效模式。

**第一层：约束生成空间**
最直接的手段是限制模型能说什么。比如用 JSON Schema 约束输出结构，用枚举字段限定取值范围。但结构化输出只保证格式，不保证内容真实。更硬核的是约束解码（constrained decoding），在 token 采样时屏蔽非法 token。vLLM 的 guided decoding 或 Outlines 可以在语法层面强制模型输出合法 JSON、正则匹配或选项列表。代价是采样空间被裁剪后，模型可能被迫选择低概率路径，导致语义质量下降。我遇到过强制枚举时模型把“不确定”硬塞进“是/否”的情况，反而增加错误。所以约束要配合“未知”选项。

**第二层：检索增强与引用**
RAG 的核心不是“给模型更多上下文”，而是“让模型只能基于给定证据回答”。实现上，检索片段要带唯一 ID，提示词里要求每个断言后标注来源 ID。生成后解析引用，检查每个 ID 是否真实存在于检索结果中。这能抓住“编造引用”的幻觉。但模型可能引用正确 ID 却曲解内容，所以还需要下一步验证。

检索本身也有坑：chunk 太大引入噪声，太小丢失上下文。我的经验是 256-512 token 的滑动窗口，重叠 20%，配合 reranker 取 top-3。embedding 模型选型要看领域：通用模型在医学文本上召回率会掉，需要领域微调或混合 BM25。

**第三层：验证器与一致性检查**
生成后验证比生成时约束更灵活。常见做法：
- **NLI 验证**：用一个小型自然语言推理模型判断“检索片段是否蕴含生成断言”。不蕴含就标记。成本低，但对数值和否定句敏感。
- **自一致性**：同一问题采样多次，看答案是否稳定。不稳定说明模型不确定，触发拒答或人工复核。代价是延迟翻倍。
- **规则校验**：数值范围、单位、日期格式用代码检查，比模型可靠。

在手术 Agent 中，我们让模型输出操作建议，然后用规则引擎检查器械是否在允许列表、剂量是否超限。规则层永远不省略。

**第四层：拒答与降级**
最被低估的手段是让模型说“我不知道”。训练时加入拒答样本，提示词里明确“若证据不足，输出 INSUFFICIENT_EVIDENCE”。但模型有谄媚倾向，需要校准：用验证器分数设阈值，低于阈值强制拒答。拒答率要监控，太高说明检索或提示词有问题，太低说明阈值太松。

**评估与观测**
离线用标注集算 hallucination rate（断言中无证据支持的比例）和 refusal rate。线上记录每次请求的检索命中、验证分数、是否拒答，做分布监控。发现某类 query 的验证分数骤降，往往是检索索引更新或模型版本切换导致。

**开放问题**
验证器本身也会幻觉，尤其是 NLI 模型对长文本。级联多个验证器成本高，如何动态分配预算仍是工程难题。另外，拒答的用户体验和安全性之间的平衡，目前更多靠产品策略而非算法。

总之，幻觉控制是系统工程：约束缩小空间，检索提供依据，验证兜底，拒答保安全。没有银弹，只有层层设防和持续观测。
