在生产环境部署 LLM 时，幻觉是必须直面的问题。尤其在医疗、金融等高风险领域，一个看似合理的错误回答可能导致严重后果。本文基于我在手术视觉辅助 Agent 和临床信息检索系统中的实践，讨论幻觉控制的四个层面：约束、检索、验证与拒答，并分享其中的权衡与失败模式。

## 1. 约束：从解码阶段降低幻觉概率

约束的核心是限制模型的输出空间。常见手段包括：

- **结构化输出**：通过 JSON Schema 或语法约束（如 GBNF）强制模型输出合法结构。例如，在手术 Agent 中，工具调用必须符合预定义的参数模式，避免模型编造不存在的函数名。
- **词汇表限制**：对于分类或实体识别任务，使用 logit bias 或受限解码，将输出限制在候选集合内。比如，在药品名称识别时，只允许输出检索到的药品词典中的条目。
- **上下文约束**：在 prompt 中明确声明“仅基于以下文档回答”，并设置低 temperature（如 0.1）。但注意，低 temperature 并不能消除幻觉，只是减少随机性。

**权衡**：约束过强可能损害模型泛化能力，尤其当候选集不完整时，模型会被迫选择错误选项。我们的经验是：对高风险字段（如剂量、解剖位置）施加硬约束，对描述性文本保留一定自由度。

## 2. 检索：用外部知识锚定生成

检索增强生成（RAG）是缓解幻觉的主流方案，但检索本身可能引入新问题。

- **分块策略**：临床指南文档通常较长，我们采用滑动窗口分块（chunk size 256 tokens，重叠 64 tokens），并保留章节标题作为元数据。过大的分块会稀释关键信息，过小则丢失上下文。
- **嵌入与重排**：使用领域适配的嵌入模型（如 BioBERT 变体）进行初步检索，再用交叉编码器重排 top-20 结果。重排能显著提升相关性，但增加约 80ms 延迟。
- **检索失败模式**：当查询与文档表述差异大时（如患者口语描述 vs 医学术语），召回率下降。我们通过查询扩展（同义词、缩写展开）缓解，但可能引入噪声。

**关键点**：检索到的内容必须可追溯。我们在生成时要求模型引用来源片段 ID，便于后续验证和用户核查。

## 3. 验证：生成后的自动检查

即使有约束和检索，模型仍可能产生与检索内容矛盾的陈述。我们采用多级验证：

- **一致性检查**：将生成答案与检索片段进行语义相似度比对（如使用 NLI 模型），标记低置信度句子。
- **规则校验**：对结构化字段（如数值、单位）进行正则或单位换算检查。例如，剂量“10mg”不能超出药品说明书范围。
- **自洽性验证**：让模型对同一问题生成多个答案（temperature>0），若答案间矛盾则触发人工审核。但这种方法成本较高，仅用于关键决策。

**失败案例**：早期我们仅依赖 NLI 验证，但模型对否定句处理不佳（如“无禁忌症” vs “有禁忌症”），导致漏检。后来引入基于规则的否定检测模块。

## 4. 拒答：知道何时说“不知道”

拒答是最后一道防线。我们设计了三类触发条件：

- **检索置信度低**：当重排分数低于阈值（如 0.3）时，直接回复“根据现有资料无法回答”。
- **验证失败**：若一致性检查发现矛盾句子占比超过 20%，则拒绝生成完整答案，转而提供相关片段。
- **超出范围**：通过意图分类器识别问题是否属于系统覆盖领域（如手术 Agent 不回答术后用药问题）。

**权衡**：拒答率过高影响用户体验。我们通过监控拒答原因分布，持续优化检索和验证阈值。目前系统拒答率约 8%，其中 70% 为检索置信度低所致。

## 工程实现与监控

- **流水线设计**：将上述步骤实现为可观测的流水线，每个阶段输出中间结果（检索片段、验证分数、拒答原因），便于调试。
- **延迟预算**：端到端延迟需控制在 2s 内。我们为检索分配 300ms，生成 800ms，验证 200ms，剩余为网络开销。
- **评估方法**：构建包含 500 条标注数据的测试集，涵盖事实性、数值、否定句等场景。主要指标：幻觉率（人工评估）、拒答准确率、端到端延迟。

## 开放问题

- 如何平衡约束强度与泛化能力？目前靠人工调参，缺乏理论指导。
- 验证环节的 NLI 模型本身可能产生误判，如何评估验证器的可靠性？
- 在多轮对话中，如何维持一致的拒答策略？

幻觉控制没有银弹，需要根据业务场景在约束、检索、验证和拒答之间找到平衡。以上经验来自实际系统迭代，希望对同行有所启发。
