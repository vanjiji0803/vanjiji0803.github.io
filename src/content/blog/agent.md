很多 Agent demo 死在第一句话上：用户说“帮我把上周那个手术视频的出血片段标一下”，系统要么直接调错工具，要么回一句“我不太明白”。意图识别不是分类问题，而是把自然语言映射成可执行任务状态的问题。

## 意图不是标签，是状态

传统 NLU 把意图当分类：`intent=query_video`。但 Agent 需要的是结构化状态：

```json
{
  "goal": "annotate_bleeding_segments",
  "slots": {
    "video_ref": "上周那个手术视频",
    "label": "bleeding",
    "time_range": null
  },
  "missing": ["video_id", "time_range"],
  "confidence": 0.72
}
```

关键在 `missing` 和 `confidence`。前者驱动追问，后者决定是否走澄清分支。没有这两个字段，Agent 只能二选一：硬猜或放弃。

## 三层解析：规则、检索、LLM

我的做法是三层串联，而不是全丢给 LLM。

**第一层：确定性规则。** 命令式前缀（“取消”“重试”）、显式 ID、时间表达式用正则和轻量 parser 处理。成本接近零，延迟 <5ms。

**第二层：检索对齐。** 把历史任务描述、工具 schema、领域实体做成 embedding 索引。用户话语先检索 top-k（k=5~10），拿到候选 goal 和实体。这一步解决“上周那个视频”这类指代——检索能召回最近的任务记录。

**第三层：LLM 结构化输出。** 只在前两层置信度不足时调用，输入是用户话语 + 检索候选 + 槽位 schema，输出严格 JSON。用 function calling 或 JSON mode，temperature=0。

这样做的原因是 token 预算：全量 LLM 解析每轮 800~1500 token，三层串联后平均降到 300 以下，P95 延迟从 1.8s 降到 600ms。

## 歧义与追问策略

歧义分两类：**槽位缺失**和**指代模糊**。前者好办，按 `missing` 列表追问。后者要小心：

- “上周那个视频”检索到 3 条记录，相似度都在 0.8 以上 → 列出选项让用户选，不要猜。
- 相似度最高 0.85、次高 0.6 → 可以带假设执行：“我理解是周三那台腹腔镜，对吗？”

追问次数要设上限。我的经验是单轮最多 2 个问题，连续 2 轮未收敛就降级到人工或给出明确的能力边界。无限追问是 Agent 体验最差的反模式。

## 任务状态机

解析结果要落到状态机，而不是直接触发工具：

```
IDLE -> PARSING -> NEEDS_CLARIFICATION -> READY -> EXECUTING -> DONE/FAILED
```

每个状态有明确的进入条件和超时。`NEEDS_CLARIFICATION` 状态要保存原始话语和部分槽位，用户补充后做增量合并，而不是重新解析整句。增量合并的坑在于槽位冲突：用户先说“昨天”，后说“不对，是前天”，需要版本号或时间戳决定覆盖顺序。

## 失败模式

1. **过度自信**：LLM 对模糊指代给出 0.9 置信度。对策是校准——用历史标注数据画 reliability diagram，温度缩放或直接对指代类槽位打折。
2. **槽位幻觉**：用户没提时间，模型补了个“今天”。对策是 schema 里区分 `explicit` 和 `inferred`，inferred 槽位执行前必须确认。
3. **工具名漂移**：检索候选里没有正确工具，LLM 编一个相近的。对策是输出后做白名单校验，不在注册表里的直接拒绝。
4. **多意图混杂**：“标出血片段然后导出报告”包含两个任务。简单做法是拆成子任务队列，复杂依赖（导出需要标注完成）用 DAG 表达。

## 评估

不要只看 intent accuracy。我关注四个指标：

- **槽位级 F1**：按槽位类型分开统计，指代类槽位单独看。
- **追问率**：过高说明解析太保守，过低说明在硬猜。
- **首轮可执行率**：用户第一句话后无需追问即可进入 READY 的比例。
- **错误执行成本**：调错工具的代价远高于多问一句，评估时要加权。

评估集要包含真实的长尾表达，而不是模板生成的句子。我一般从线上日志采样 200~500 条人工标注，每两周更新一次。

## 还没解决的问题

跨会话的意图继承：用户昨天说“处理那批数据”，今天说“继续”，状态怎么恢复？目前靠会话摘要 + 检索，但摘要本身会丢信息。另一个是工具 schema 变更后的兼容性——检索索引和 LLM prompt 都要同步更新，目前还是手动流程。这两个问题我还没有干净的工程解，欢迎讨论。
